# 호출 시점의 커밋 검증

1. 첫 작업으로 대상 작업 트리에서 `py -3 <스킬 폴더>/scripts/capture.py`를 실행한다. 커밋이 없는 저장소면 그 사실을 보고하고 종료한다. 출력된 실행 폴더의 `snapshot.json`에서 전체 SHA를 읽는다. 같은 커밋을 다시 호출해도 기록은 각각 보관한다.
2. 임시 디렉터리에 `git clone --local --no-checkout <대상 작업 트리 경로> <복제 경로>`로 복제하고 그 안에서 `git checkout --detach <기록된 SHA>`를 실행한다. 복제본의 HEAD가 기록과 일치하는지 확인한다. 실패하면 원인을 실행 폴더의 `result.md`에 기록한다. 이후 모든 파일 조회와 테스트는 해당 복제본에서 한다.
3. `git show --format=fuller --stat <SHA>`로 커밋을 확인하고 실제 패치를 읽는다. 일반 커밋은 부모와 비교하고, 최초 커밋은 `git show --root <SHA>`, 병합은 `git diff <부모 SHA> <SHA>`로 각 부모와 비교해 병합 결과를 확인한다.
4. 복제본의 AGENTS.md, docs/MAP.md, docs/CONVENTIONS.md와 변경 영역 문서를 기준으로 버그·회귀·컨벤션·문서 일치를 검토한다. 게임 동작 변경은 해당 Unity 버전과 CLI로 정상·경계·실패 사례를 실행하고 개별 결과를 확인한다. 필요한 임시 테스트는 복제본에 작성한다. 도구 변경은 실제 동작을, 문서 변경은 링크와 설명을 확인한다.
5. 실행 폴더의 `result.md`에 기록 시각, 전체 SHA, 판정(통과·문제 발견·검증 미완료), 실행한 명령과 결과를 남긴다. 발견한 문제에는 파일·재현 방법·수정 방향을 적고 실행하지 못한 검사는 사유를 적는다. 필요한 검사가 모두 통과해야 통과로 기록한다. 사용자에게 SHA, 판정, 결과 파일 경로를 보고한다.
6. 복제본에서 열었던 에디터를 닫는다. 성공 시 이번 실행이 만든 임시 복제본을 정리하고, 실패 시 재현 경로를 결과에 남긴다. 원본의 작업 트리·인덱스·브랜치 및 원격은 검증 대상 조회에만 사용한다.
